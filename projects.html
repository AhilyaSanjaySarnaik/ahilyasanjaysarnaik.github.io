Cloud · Detection & responseJun 2026

AWS automated threat detection & response

Cloud attacks such as opening SSH to the internet, backdooring an S3 bucket or switching off CloudTrail do their damage in minutes. I wanted the response to happen in seconds, without a human in the loop.

  • 4 Python responders on Lambda, triggered by EventBridge rules over CloudTrail and GuardDuty findings, each remediating one attack technique.
  • Deployed with Terraform, one least-privilege IAM role per responder, plus dry-run mode for safe testing.
  • Validated against real attack techniques using Stratus Red Team in a sandbox account.
  • SNS alerting, CloudWatch metrics and Athena queries over CloudTrail for investigation; pytest with mocked AWS in a GitHub Actions CI pipeline.

AI security · Authorization2026

SupervisorGuard AI: runtime enforcement for MCP agents

AI agents connected to real tools can be talked into doing things their user never approved. Model output can't be the security boundary, so the boundary has to sit between the agent and the tool.

  • Security layer that intercepts every agent tool call to the official GitHub MCP server before it executes, tested against live GitHub API calls.
  • Enforces API-key identity, input sanitisation, attribute-based access control per tool, and human approval for destructive actions such as merges.
  • Every denial is written to a security log, so blocked attempts can be investigated afterwards.

AI security · Prompt injection2026

Agentic firewall & MCP tool sanitizer

AI coding agents read untrusted text all day. Single-layer filters are either too strict or easy to bypass, and a poisoned MCP tool can leak secrets without any obviously bad prompt.

  • Four-layer screen for prompts and commands: regex rules, a gibberish heuristic, a fine-tuned DeBERTa classifier, and similarity matching against known attacks.
  • Sanitizing proxy hides poisoned MCP tools, including tool pairs that only leak secrets when used together.
  • Every block is audit-logged with the layer that caught it.

IAM · Healthcare AIJan 2026

MedGuard: access governance gateway for clinical AI

An AI assistant in a hospital should only ever see the records of patients its user is assigned to, and patient data must never leak in its answers.

  • Fail-closed gateway with policies in Open Policy Agent (Rego): no decision means no access.
  • Issues single-use, 30-second capability tokens bound to one user, one tool and one patient.
  • PHI scrubbing on output and a JSON audit event for every allow and deny decision.
  • Threat model mapping 7 threats to a control and a test each, backed by 28 automated tests.

Research · MSc thesisSep 2026

Adaptive honeypot architecture

Static honeypots are easy for attackers to fingerprint. Can a honeypot change how it looks as an attacker becomes more hostile, and stay lightweight while doing it?

  • Python honeypot that changes its SSH and HTTP identity, status codes and response timing as the attacker's threat score rises.
  • Threat scoring with entropy and Bayesian updating, driving a finite-state engine.
  • Benchmarked against Cowrie, Dionaea, Heralding and Elasticpot across 91 attack runs in an isolated lab, using packet captures, container metrics and logs.

Recon · AI guardrails2026

AI attack-surface intelligence platform

Recon produces long lists of assets that someone has to triage. A local LLM can help, but the LLM itself becomes an injection target.

  • Passive recon from DNS and certificate-transparency logs builds an asset inventory.
  • A local LLM (Ollama) triages each asset from P1 to P4 and writes a report in Markdown or Word.
  • Guardrail layer redacts PII and scores injection risk before anything reaches the model.

SOC · SIEMJan 2025

SOC home lab: SIEM monitoring & threat detection

Detection rules are only useful if you've seen what the attack looks like in your own logs. I built a lab to generate that evidence and practise investigating it.

  • Virtualised environment forwarding Windows Sysmon telemetry to Splunk for central logging and endpoint monitoring.

Research · ML security2026

Federated intrusion detection on skewed traffic

In federated learning each organisation's network traffic looks different. Standard averaging (FedAvg) breaks down when that data is highly skewed.

  • Designed adaptive gated aggregation for federated intrusion detection across non-IID clients.
  • Raised F1 from 0.68 to 0.81 over FedAvg on highly skewed traffic at about a 5% false-alarm rate.
